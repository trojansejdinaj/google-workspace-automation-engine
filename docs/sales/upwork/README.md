# Upwork Sales Assets

## Purpose

This folder contains copy/paste-ready material for presenting the Google Workspace Automation Engine in an Upwork portfolio and responding to relevant job posts. The assets translate the repository's technical proof into client-readable language without claiming client deployments, production scale, revenue impact, or unmeasured time savings.

## Assets

- [Portfolio project entry](portfolio-project.md) — title, overview, proof highlights, technology, limitations, and screenshot order for an Upwork portfolio project
- [Proposal templates](proposal-templates.md) — short and detailed proposals, discovery questions, package ideas, promise boundaries, and closing lines
- [Full portfolio case study](../../case-studies/google-workspace-automation-engine.md) — the detailed problem-solution-proof narrative behind the sales copy
- [Project README](../../../README.md) — project capabilities, setup, evidence model, and quality gates

## How to use these assets

1. Choose the proposal closest to the job's actual problem.
2. Replace every bracketed placeholder with details from the job post or discovery call.
3. Remove features that are outside the requested scope.
4. Link or attach only the proof relevant to the proposal.
5. Confirm credentials, Google Workspace permissions, input formats, exception rules, and delivery expectations before pricing.
6. Recheck every factual claim against the case study and proof files before sending.

Do not send a template unchanged. A concise proposal that names the client's current process, desired output, and main risk is stronger than a generic list of features.

## Claim and security guardrails

- Keep claims tied to the controlled runs documented in the proof files.
- Describe the Gmail live proof account only as `cloud google acc`.
- Do not describe the workflows as client deployments or production-scale systems.
- Do not invent guarantees, rankings, client names, financial results, or time-saved figures.
- Do not publish credentials, OAuth material, private account identifiers, real Sheet IDs, local configuration, or generated operational run folders.
- Tailor scope and pricing only after the client's requirements and access constraints are confirmed.
